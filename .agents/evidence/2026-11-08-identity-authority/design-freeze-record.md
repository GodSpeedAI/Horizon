## Post-review corrections

These edits were made after the last reviewed snapshot. They were not reviewed, and they are not claimed to be reviewed.

**REQ-SEC-006 alignment.** Checking the design against the frozen specification found a real contradiction. Stage 0B bound `confirmer_ref` to the OS login and required it to match the pending record's requester. REQ-SEC-006 (spec 1.2.0, approved 2026-11-02, which explicitly supersedes "the `local_operator` OS-session wording") requires operator identity to be a configured durable operator actor bound to a registered WebAuthn credential and mapped to a SEA-Forge actor, with the OS account diagnostic only. The affected text was corrected:

- The OS-authentication bullet separates presence from identity, resolves `confirmer_ref` through the repo's existing operator-actor validation (`validateOperatorActors` / `HORIZON_OPERATOR_REF`), records the OS session as `presence_evidence.os_session`, and refuses on operator-actor mismatch rather than OS-user mismatch.
- The `horizon confirm` bullet no longer states the OS login as its identity precondition.
- The pending-descriptor field list now names `confirmer_ref` and `presence_evidence`, so the invariant is machine-checkable rather than prose.
- The Stage 0B test description no longer asks `test/desk-write-token.test.ts` to prove OS-user refusal; it now names presence refusal and operator-actor mismatch. The existing test file asserts neither today, so this is a Stage 0B addition, not a description of current coverage.

**Why the first three of those landed after the others.** The session making this correction terminated on an account quota immediately after its first edit. The remaining contradictions were therefore left in the document for a later pass, which is how the freeze record and delta came to describe a file state that no longer existed. The record above now matches the file on disk.

**Standing disposition.** All five post-owner-correction edits move to Stage 0A as machine-checked contract fixtures and negative tests. A regression should fail a test, not require a reader. No further prose review cycle is planned, and none of these edits should be cited as reviewed.
**Ask-row executor correction.** The two recorded identity defects were open violations of the design's own vocabulary: section 2 defines the executor as "the agent or service acting", while the Appendix A P2/P3 table named a human session as the executor of `ask.route`, whose only handler runs on the agent door under a registered agent key. The table cell for `ask.route` now names the agent execution, and the cell for `ask.withdraw` names both callers, because that row carries the person's `human.stop_waiting` on the desk route and the agent's `ask.withdraw` on the agent door. A third normative clarification paragraph records why. Nothing else moves: the class, the authority writer, the human predicate and the pending expiry are unchanged, so the agent proposes and the human authorises. This correction was not independently reviewed either; it is guarded by the Stage 0A catalog row and the defect-remediation negative tests, and the defect record names the divergence that it corrects.

**Stage 0A remediation wave.** The independent Stage 0A review of the frozen contract set returned REJECT. Its five blocking findings were all true, and each was corrected in the contract set rather than in prose alone: section 11 names every reconciled operation ID and adds the freeze's live-enforcement tables (what the running code enforces today, what is missing, and the stage that closes it); section 12's frozen parameter table is replaced field for field by the frozen schemas and is now checked against the live handlers by a build check; the record contract gains the `PendingOperation` kind and its three constraints; Appendix A names that record and its authority rule; the Stage 0B boundary states that the browser's pairing route is `session.pair` and not the reserved `device.pair`; and the Review Record states what the review found and what remains outstanding. The `ask.route` residual in the catalog's defect record is updated to match the amended design, so the two files no longer describe a divergence that no longer exists.

A second independent review of the corrected, re-frozen contract set is the condition for Stage 0A to settle. That round has not run at the time this row was written. This row claims no acceptance: it is "not re-reviewed" until the round-2 verdict says otherwise, and the verdict will be retained in `.agents/evidence/2026-11-09-stage-0a-defects/` beside the frozen copy it read.
**Stage 0A round-2 remediation wave.** The second independent review of the re-frozen contract set returned **REJECT**: five blocking findings, seven must-fix findings and four advisories. Every one was a real disagreement between the design and the contract set, or between the contract and the code it governs, and each was corrected in the contract set and in this file together. Section 12's parameter table is now generated from `contracts/identity/v1/params.yaml` and compared with it byte for byte by `scripts/check-design-contract-consistency.ts`, so the two cannot drift; Appendix A's P2/P3 policy table uses the canonical evidence vocabulary the A3 mechanism declares; the `A3Receipt` row carries `protected_terminal_presence` as a separate boolean claim beside the predicate rather than as a third predicate; the Stage 0B tables name only the operations Stage 0B can actually authorise, and `ask.route` is explicitly not one of them; the pairing route's caller path is the code holder proving possession of a one-time code, not the local console; and the parameter table is accompanied by the rule that every live-bound P0/P1 row names its own schema. The Review Record now also says where the third verdict lives: beside the frozen copy it read, rather than in this file, because editing this file after the verdict would break the hash pin the remediation preregistration carries.
**The entitlement correction.** The round-2 review's fifteenth finding said the human entitlement had no frozen interface: the contract named an `entitlement_ref` and nothing said what the thing behind it was, so currentness, scope, subject, issuer, epoch, and expiry could not be checked by anyone. The contract now carries `contracts/identity/v1/external-interfaces.json`, which names the SEA-Forge interfaces Horizon consumes — the authority decision and the action grant, pinned to the commit they were read at, and the human entitlement, which the owner has not published — and declares the facts each one must carry. The record contract binds an entitlement-backed decision or fence to those facts, so a name alone is no longer authority, and the design's new section 9.1 carries a table generated from that contract. The owner's publication of the entitlement artifact is an external dependency of the governed human path, and the contract says so instead of pretending the artifact exists.
A third independent review of the corrected, re-frozen contract set is the condition for Stage 0A to settle. That round has not run at the time this row was written. This row claims no acceptance: it is "not re-reviewed" until the round-3 verdict says otherwise, and the verdict will be retained in `.agents/evidence/2026-11-09-stage-0a-defects/` beside the frozen copy it read.
