## The one thing that is not live: the agent's panel calls (journeys 5, 6, 7 panel part)

The running desk has no way to receive an agent's panel call. `applyAgentOp` (`src/app.ts:1809`, handed out at `src/app.ts:2109`) is reachable only from inside the server process. `/desk/panels/op` takes the person's operations only, and an agent on the page is refused there with 403 (journey 4). Nothing else in the repo calls it except tests.

So for journeys 5, 6 and the panel half of 7, the agent side is a **stand-in** (`panel-harness.ts`). It keeps the panel board in the test script using the desk's real reducers (`reduceAgent`, `reduceHuman`), the real grammar and the live `/desk/panels/catalogue` examples. It answers the page's `/desk/state.json` (panels only), `/desk/conversation` (adds the panel and answer rows the server would add) and your `human.answer` call. The page, its client code and every drawer are the real built code. Everything else still goes to the live server. Treat 5 and 6 as "real page, real reducers, stand-in server for panels". To make them fully live, the server needs a route or a tool that calls `applyAgentOp`; then `j5.ts` can be pointed at it by deleting `installHarness`.

## Bugs

Fixed (small, inside `src/ui/desk/**`, each with a test in `test/desk-conversation.test.tsx`):

1. **409 in the console when you Confirm an agent's waiting suggestion.** The composer saved the suggestion's words under the suggestion's own draft id; the server keeps one draft and refuses another id (correct, as designed), which showed as a red 409 on every Confirm. Fix: `src/ui/desk/Composer.tsx` no longer autosaves under a proposal's id (`keepsDraft`, `proposalDraft`). Verified live: 0 console errors. Commit `5f7a434`.
2. **Sideways scroll at 390 px with a chart or graph in a conversation row.** The row (a one-column grid) grew to its widest child. Fix: `.cv-row` now has `grid-template-columns:minmax(0,1fr); min-width:0` (`src/ui/desk/desk.css:184`) and the chart contains its hidden table (`src/ui/desk/blocks/blocks.css`). Verified live: scrollWidth 390. Commit `a727143`.
3. **axe `heading-order` and `landmark-unique` on Conversation.** The waiting card was a named region with an h3 right under the h1, and two waiting cards had the same name. Fix: the card is an article with an h2 (`Conversation.tsx:61`), panel cards are h2 (`Panels.tsx:115`), part titles are h3 (`blocks/shared.tsx:35`). Verified live: 0 violations. Commit `3c7c125`.

Not fixed (reported; the first two are server side and need your restart):

A. **No live door for an agent's panel calls.** See the top of this file. `src/app.ts:1809`, `src/app.ts:2109`.
B. **The answer rows show raw ids and never finish.** After you answer, the row says "You answered: plan_a" (the option's id, not "Plan A"; for yes/no it says Yes or No, for several it joins the ids) from `src/app.ts:1862-1863`. After the agent routes it, a second row "Your answer to which_way" (the question's id, not its words) is added at `src/app.ts:1819`, and the first row stays "Waiting for you" for good. The part itself shows the right words; only the conversation rows do not. This is the one place a raw id reaches the visible Conversation. It needs the label in the row and the first row marked done when routed.
C. **Observation, not a failure.** The Conversation header "Needs you (n)" counts open questions only (`Conversation.tsx:94`), so with 1 waiting proposal and 15 steps waiting in Decide it reads "Needs you (0)" while the status bar says "Needs you: 15". A waiting proposal is a thing that needs you; you may want it counted.
D. **Observation.** Once a panel has no open question it folds, and the "You answered ... Waiting for the agent ..." echo sits inside the closed fold. It shows on opening the card; the conversation row below carries the "Waiting for the agent to say where it went." line. By design, but easy to miss.
E. **Not exercised live:** the "preview is out of date, show the new preview" path of journey 3 (it never happened in any run), the Agent (not on this page) badge outside the stand-in, and Presenting stand-ins inside agent-written panel text.
